# Domain Docs

This is a single-context repository.

## Before exploring

- Read the root `CONTEXT.md` glossary.
- Read relevant decisions under `docs/adr/` when that directory exists.
- If a referenced document does not exist, proceed silently. Domain-modeling creates it only when a term or durable decision is resolved.

## Use the glossary's vocabulary

Use terms from `CONTEXT.md` in issue titles, specifications, tickets, tests, and code. If a required concept is absent, determine whether it is a real domain-language gap before adding it.

## Flag decision conflicts

If proposed work contradicts an existing architectural decision, surface the conflict explicitly instead of silently overriding it.
